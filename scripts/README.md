# 🛠 Setup Dev Environment

Скрипт для автоматической настройки базовой инфраструктуры проекта:

- ESLint (проверка кода)
- Prettier (форматирование)
- Husky (git hooks)
- lint-staged (проверка staged файлов)
- commitlint (контроль сообщений коммитов)
- TypeScript config
- VS Code настройки
- .gitignore

---

## 🚀 Быстрый старт

После инициализации проекта запустить

```bash
node scripts/setup-dev.js
```

---

## ⚙️ Что настраивается

### ✅ ESLint

- Проверяет JS / TS / Vue
- Предупреждает про `console`
- Предупреждает про неиспользуемые переменные

---

### ✅ Prettier

- Автоформатирование кода
- Работает при сохранении (VS Code)

---

### ✅ Husky + lint-staged

При коммите:

1. Проверяются только изменённые файлы
2. Запускается:
   - eslint --fix
   - prettier

Если есть ошибки → коммит отклоняется

---

### ✅ TypeScript check

Перед коммитом выполняется:

```bash
tsc --noEmit
```

👉 если есть ошибки типов — коммит не пройдет

---

### ✅ Commitlint

Все коммиты должны быть в формате:

```bash
type: сообщение
```

### Примеры

```bash
feat: добавить авторизацию
fix: исправить баг с API
chore: обновить зависимости
refactor: упростить код
```

❌ Нельзя:

```bash
test
my commit
123
```

---

## 🧠 Зачем это нужно

Этот скрипт решает сразу несколько проблем:

- единый стиль кода в команде
- отсутствие “сломанного” кода в репозитории
- контроль качества перед коммитом
- предсказуемые commit-сообщения (удобно для changelog)

---

## ⚠️ Требования

Перед запуском убедитесь:

- установлен Node.js (рекомендуется >= 18)
- установлен npm
- инициализирован проект (есть package.json в корне)
- инициализирован git репозиторий:

```bash
git init
```

---

## 🧪 Проверка

Попробуйте:

```bash
git commit -m "test"
```

👉 коммит должен упасть

Теперь правильно:

```bash
git commit -m "feat: initial setup"
```

👉 коммит пройдет ✅
